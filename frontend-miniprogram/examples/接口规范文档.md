# Auth 登录模块接口规范文档

## 概述

本文档详细描述了登录认证模块（Auth）的API接口，包括微信登录、用户登出、微信配置等功能。

## 基础URL

```
http://localhost:8000/api/v1
```

## 认证方式

登录成功后，后续接口需要通过 `Authorization` 头部携带 token：

```
Authorization: Bearer {token值}
```

## 响应格式

所有接口返回JSON格式数据，通用响应结构如下：

```json
{
  "code": 2000,
  "message": "success",
  "data": {}
}
```

## 状态码说明

| code | 常量名 | 含义 |
|------|--------|------|
| 2000 | OK | 请求成功 |
| 4000 | BAD_REQUEST | 请求参数错误 |
| 4001 | UNAUTHORIZED | 未授权访问（未登录） |
| 4002 | FORBIDDEN | 禁止访问（权限不足） |

## 用户类型说明

| userType | 说明 |
|----------|------|
| 0 | 普通用户 |
| 1 | 企业用户 |
| 2 | 科研团队用户 |
| 3 | 管理员用户 |

## 接口详情

### 1. 微信登录

- **接口地址**: `POST /auth/wechat-login`
- **说明**: 使用微信授权码进行登录，如果用户不存在则自动创建新用户
- **请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| code | string | 是 | 微信授权码 |

- **请求示例**:

```json
{
  "code": "091ABC234DEF567"
}
```

- **成功响应示例**:

```json
{
  "code": 2000,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userId": "user001",
    "userType": 0,
    "account": {
      "id": "user001",
      "username": "wx_user_001",
      "userType": 0,
      "wechatNickname": "张三",
      "wechatAvatar": "https://xxx.com/avatar.png",
      "status": 1,
      "createTime": "2024-01-01T10:00:00",
      "lastLoginTime": "2024-01-15T15:30:00"
    }
  }
}
```

- **失败响应示例**:

| code | message | 说明 |
|------|---------|------|
| 4000 | 登录失败：缺少code参数 | code参数为空 |
| 4000 | 微信登录失败 | 微信API调用失败 |
| 4000 | 用户账号已被禁用 | 用户状态为禁用 |

### 2. 账密登录

- **接口地址**: `POST /auth/login`
- **说明**: 使用用户名和密码进行登录
- **请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

- **请求示例**:

```json
{
  "username": "admin",
  "password": "admin123"
}
```

- **成功响应示例**:

```json
{
  "code": 2000,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userId": "user_admin001",
    "userType": 3,
    "account": {
      "id": "admin001",
      "userId": "user_admin001",
      "realName": "管理员",
      "roleId": "role_super_admin"
    }
  }
}
```

- **失败响应示例**:

| code | message | 说明 |
|------|---------|------|
| 4000 | 登录失败：缺少用户名 | username参数为空 |
| 4000 | 登录失败：缺少密码 | password参数为空 |
| 4000 | 用户名或密码错误 | 用户不存在或密码错误 |
| 4000 | 用户账号已被禁用 | 用户状态为禁用 |

### 3. 用户登出

- **接口地址**: `POST /auth/logout`
- **请求头**: 可选携带 `Authorization`，如未携带则仅清除本地上下文
- **说明**: 使当前用户token失效，并清除用户上下文

- **请求示例**:

```javascript
fetch('/api/v1/auth/logout', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer ' + token
  }
});
```

- **成功响应示例**:

```json
{
  "code": 2000,
  "message": "退出成功",
  "data": null
}
```

### 4. 获取微信配置

- **接口地址**: `GET /auth/wechat-config`
- **说明**: 获取微信小程序配置信息

- **成功响应示例**:

```json
{
  "code": 2000,
  "message": "配置信息",
  "data": {
    "appId": "已配置",
    "appSecret": "已配置",
    "loginUrl": "https://api.weixin.qq.com/sns/jscode2session"
  }
}
```

  "code": 2000,
  "message": "修改密码成功",
  "data": null
}

| code | message | 说明 |
|------|---------|------|
| 4000 | 旧密码不正确 | 旧密码验证失败 |

### 5. 更新用户状态（启用/禁用）

- **接口地址**: `PATCH /users/{userId}/status`
- **请求头**: 需要认证
- **路径参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | string | 是 | 用户ID |

- **请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| status | integer | 是 | 状态：0=禁用，1=启用 |

- **业务说明**:
  - **禁用用户（status=0）**：立即清除该用户的所有 Redis 登录缓存，强制用户下线。用户下一次请求将被拒绝。
  - **启用用户（status=1）**：更新缓存中的用户状态，用户可正常登录使用系统。

- **请求示例**:

```json
{
  "status": 0
}
```

- **成功响应示例**:

```json
{
  "code": 2002,
  "message": "用户状态更新成功",
  "data": null
}
```

## 基础URL

```
http://localhost:8000/api/v1
```

## 认证方式

所有接口需要认证，认证通过在请求头中添加 `Authorization` 字段实现：

```
Authorization: Bearer {token值}
```

## 响应格式

所有接口返回JSON格式数据，通用响应结构如下：

```json
{
  "code": 2000,
  "message": "success",
  "data": {}
}
```

## 状态码说明

| code | 常量名 | 含义 |
|------|--------|------|
| 2000 | OK | 请求成功 |
| 4000 | BAD_REQUEST | 请求参数错误 |
| 4001 | UNAUTHORIZED | 未授权访问（未登录） |
| 4002 | FORBIDDEN | 禁止访问（权限不足） |
| 4003 | NOT_FOUND | 资源不存在 |

### 9. 绑定专利到用户

- **接口地址**: `POST /patents/bind`
- **请求头**: 需要认证
- **业务流程说明**:
  1. 用户在前端选择确认专利后调用此接口
  2. 后端将选中的专利绑定到当前用户
  3. 在 bound_patent 表中创建绑定记录（包含浏览数、搜索数、点击数字段，初始值为0）

- **前端调用时机**:
  - 用户在专利列表中选择若干专利后点击"确认绑定"按钮
  - 需传入用户选择的专利ID列表

- **注意事项**:
  - 用户必须已登录（通过 UserContext 获取用户ID）
  - 支持两种用户类型：enterprise（企业用户）、research_team（科研团队用户）
  - 已绑定的专利会被自动跳过，不会重复绑定

- **请求参数**:

| 参数名 | 类型 | 必填 | 说明 |

## 特殊规则说明

### 1. 管理员创建规则

- 管理员不能主动注册，必须由已有管理员升级普通用户
- 被升级的用户必须是已注册的普通用户
- 如果未指定角色，默认分配"空白角色"（BLANK）

### 2. 权限继承规则

**角色创建/修改/删除**:
- 所有管理员都能创建/修改/删除角色，但只能操作权限范围 ≤ 自己权限的角色
- 目标角色的每个权限值都不能超过操作管理员的对应权限
- 超级管理员可以操作任意权限的角色

**管理员分配**:
- 管理员只能分配自己拥有的权限
- 目标角色的每个权限值都不能超过操作管理员的对应权限
- 超级管理员可以分配任何角色

### 3. 角色复用规则

- 一个角色可以分配给多个管理员使用
- 管理员可以同时拥有一个或多个角色（通过role_id关联）

### 4. 角色删除规则

- 不能删除系统保留角色：超级管理员角色（SUPER_ADMIN）、空白角色（BLANK）
- 管理员不能删除自己的角色
- 删除角色时，使用该角色的管理员自动换为空白角色
- 删除角色时会同时删除该角色的权限配置记录

### 5. 默认角色

系统初始化时自动创建两个角色：

| roleCode | roleName | 说明 |
|----------|---------|------|
| BLANK | 空白角色 | 所有权限为0，新管理员默认角色 |
| SUPER_ADMIN | 超级管理员 | 所有权限为1，系统最高权限 |

## 前端处理建议

### 1. 认证拦截器

```javascript
// 请求拦截器
axios.interceptors.request.use(config => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// 响应拦截器
axios.interceptors.response.use(
  response => response,
  error => {
    const code = error.response?.data?.code;
    if (code === 4001) {
      // 未登录，跳转登录页
      localStorage.removeItem('token');
      window.location.href = '/login';
    } else if (code === 4002 || code === 6009) {
      // 无权限，提示用户
      alert(error.response.data.message);
    }
    return Promise.reject(error);
  }
);
```
